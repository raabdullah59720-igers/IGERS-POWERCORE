## 3. Browser UI regression

A headless Chromium regression suite used the actual `index.html` DOM/panel markup and the app-shell CSS/JS. Other application scripts and external iframes were removed from this controlled fixture to isolate navigation behavior; therefore this is an app-shell UI test, **not** a full live-provider certification.

**Result: 25 / 25 tests passed, with zero page exceptions and zero browser console errors.** Tests covered:

- Dashboard initialization and seven workspace cards.
- 34 unique canonical panel destinations; Concept / Thesis 3D Lab / FEAS aliases grouped instead of presenting the same top-level panel repeatedly.
- Workspace → panel, Back panel → workspace, Back workspace → dashboard.
- Browser Back/Forward restoration.
- Search deduplication (`toll` returns one destination) and alias search (`FEAS` opens its nested target inside the Concept panel).
- Direct deep-link opening and safe Back fallback to dashboard.
- Existing in-panel navigation and panel-to-panel Back behavior.
- `Ctrl+K` search focus and day-theme compatibility.
- Responsive widths 320, 360, 390, 768, 1024 and 1440 px without horizontal overflow.
- Mobile Back visibility and one-level return.

## 5. Runtime caveats

- External live data feeds were not independently certified for live freshness. Their behavior still depends on provider availability, browser/network/CORS policy and any required API configuration.
- A full end-to-end run of every original runtime module was not performed; the browser suite intentionally isolated the new navigation layer to avoid conflating UI regression with external network/provider failures.
- The supplied Bangladesh boundary fallback is a generalized Natural Earth 1:110m outline for visualization only, not official border or navigation data.
- Client-side access gates are UI restrictions, not server-side security controls.

## Release decision

**PASS for app-shell/navigation release testing.** The source preservation, static integrity, build, runtime asset, packaging and UI navigation checks passed. User-side verification of live data providers and individual original panel behavior after GitHub Pages deployment remains necessary because those external services were not certified by this test run.
